# Milestone Zero: A persistent two-room coastal research station

## Problem Statement
A generated image cannot be explored as stable space. Prove a real walkable world before installing generation models.

## Solution
Launch a local browser, enter a Scandinavian research station, walk through a controlled portal into a second room and return. Separate local splat and collision artifacts stay fixed. Restarting restores the world and the last saved player pose.

## User Stories
1. As a visitor, I can launch the app with one command.
2. As a visitor, I see an honest fixture-world label and can enter first-person mode.
3. As a visitor, I move using WASD and look using the mouse; Escape releases the pointer.
4. As a visitor, I cannot pass through solid walls or equipment.
5. As a visitor, I approach the northern portal and see loading progress for the second chunk.
6. As a visitor, I cross only once its visual and collider are ready.
7. As a visitor, I return without losing previously loaded scene state.
8. As a visitor, restarting preserves world identity, artifacts, portal topology and saved player pose.
9. As a developer, I inspect chunk identities, player coordinates and load state visibly.
10. As a developer, I run automated movement and persistence tests without a GPU.
11. As a developer, I inspect worker health over the same HTTP boundary used for later generators.
12. As a visitor, load failures are visible and do not create an unsafe open seam.

## Implementation Decisions
Use PlayCanvas Gaussian PLY assets with separate GLB collision boxes, authored deterministically. World units are metres, Y up, forward is -Z. Two rooms span 14×18m each with a 3.2m portal. Kinematic player radius 0.3m, eye height 1.65m; flat floors initially, no jumping/stairs. Movement uses substeps and delta clamping. A single browser client streams the second static chunk on proximity, retaining both. Mac HTTP API owns SQLite metadata and stable SHA-256 artifacts. Browser persists pose periodically and on exit. Static fixture mode is explicitly distinct from AI generation. Worker Python health/capability and delayed fixture-job API is a follow-on ticket; no model installs or GPU benchmark claims in this milestone.

## Testing Decisions
Test public HTTP behavior across close/reopen, real artifact hashes, the public move-player function against solid boundaries/portal openings, and browser behavior for rendering, entry, A→B→A and restoration. These seams follow the user's mandated acceptance loop and autonomous test policy. No prior test suite exists. A browser screenshot alone does not prove collision.

## Out of Scope
AI generation, unrestricted infinity, model downloads, arbitrary mesh collision, multiplayer, mobile walking, speculative generation and photorealistic fixture quality.

## Further Notes
Research blocking facts rather than requesting routine choices. Runtime fixtures are reproducible authored spatial splats, not generated by an AI model. M0 is green only with verified traversal and persistence; unavailable GPU access does not block the static milestone.
