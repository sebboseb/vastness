# M1 disposable generated-chunk experiment

Question: can the already-generated TRELLIS asset become a readable, walkable spatial scene, and which abstract representation deserves further investigation?

Use job `trellis-smoke-20260915-03` and verify its recorded PLY/GLB hashes. Preserve original bytes. Derive a low-detail mesh and a conservative collision proxy from the actual mesh; select and record an explicit scale. Inspect the individual asset, then compose a disposable bounded chunk with a clearly labeled authored flat floor and boundary. Model-generated asset instances supply obstacles and appearance. This experiment is not a claim of model-generated room layout or prompt conditioning.

A separate `m1-prototype.html` page loads only prototype artifacts, keeps pose in memory and never calls world/player mutation APIs. M0 source, accepted chunks and persistence remain unchanged. A prototype branch retains every visual treatment; no style is promoted to the main product in this trial.

Compare at least three distinct render representations at matched positions: faceted low-detail geometry, graphic restricted-value splats, and procedural glyph-like marks. Keep the same transforms, spatial layout, floor geometry and collider across variants. The graphic post-process intentionally recolors the complete canvas, including the shared floor; record that appearance change as a comparison limitation. An optional original-splat control helps diagnose abstraction costs. Use simple functional controls, not UI polish.

Acceptance: real asset loads in the isolated browser; collider is measurably simpler and explicitly scaled; player movement uses actual derived solids, cannot pass through obstacles/boundary and can navigate a connected route around generated forms and return. Verify loaded collider behavior at the browser seam and with movement tests, including a passage inside the original asset's overall AABB. Record matched views and observed movement, frame cost, failure cases, legibility and ambiguity. Select one provisional branch for a dedicated next ticket; no permanent visual style decision.

Preparation seam: `scripts/prepare-m1-prototype.ts` consumes the verified local evidence PLY/GLB and writes ignored `apps/web/m1-prototype-public/m1-prototype/` files. `scene.json` contains source identities, transform `{scale:number,position:[number,number,number]}`, simplified mesh `{positions:number[],normals:number[],indices:number[]}`, `boxes:CollisionBox[]` in scaled local world coordinates, `glyphs:[number,number,number][]` in the same coordinates, and numeric derivation metrics. It copies the original PLY to `scene.ply`. Geometry arrays stay in original model coordinates; the browser applies the recorded transform. Chunk instance translations apply equally to visuals and derived boxes. Lead owns the prototype page/renderer/movement tests and root configuration; geometry work owns preparation script and its tests.
